# D1A · Unified longitudinal analytics

**Decision for review.** Build one internal, read-only report over an owner's canonical observations. Its first usable result is a calendar of reported intake and individual weigh-ins that explains every blank. Extend that same calendar to explain what strength, running and recovery records support. A caller should be able to ask “which runs make up this distance, and which dates might be missing?” and get both answers from the result.

### Acquisition readiness supplied for this design

The acquisition report describes strength history across much of the period since January 2025. It also reports a fully reconciled seven-day Garmin rehearsal. In the recent 28-day block, sleep, HRV, resting HR, expenditure and intake acquisition completed on 28 days. Activity and running-instruction enumeration completed on seven days and remained partial on 21. These are category-day counts. The rehearsal and recent block need not be disjoint. A verified run on a partial day is usable immediately. Tied activity start times are under separate pagination repair. Each future report reads its own coverage and issues rather than assuming a repair succeeded.

HRV quantitative units still await verification. Energy expenditure is a wearable estimate. The intake writer and completeness of logging are unknown. Historical weight interpretation applies only within verified segments, and a recent segment is under independent verification. These are supplied readiness facts, with no personal records or provider responses inspected for D1A.

## Proposed read contract

Use one query in the existing database reader layer and pure calculations beside `analytics.strength`. For example, the first slice would accept the following internal call (proposed Python, synthetic identifiers supplied by the caller).

```python
report = query_longitudinal(
    session,
    owner_id=trusted_owner.id,
    period=Period(date(2025, 2, 3), date(2025, 2, 10), ZoneInfo("America/Toronto")),
    sources=ReportSources(garmin_account=garmin_id, hevy_profile=hevy_profile),
)
```

The caller resolves the authorized principal before opening a clean, read-only PostgreSQL REPEATABLE READ transaction, before the first SELECT. Run every selector, provenance lookup, issue check and summary in that transaction, without autoflush, writes or row locks. Reject an unsuitable caller transaction. The reader needs ordinary selects, including a nonlocking lookup for any future outcome annotation. Existing execution command paths can take locks. A read during a repair sees one side of its commit across all report tables. No provider calls, credential lookup or import are query dependencies.

Require explicit source choice for account-specific metrics. Check each requested account against the owner and provider before reading. Reject a mismatched or ambiguous selection without returning another owner's metadata. Carry account status and exclude unresolved bindings. A disconnected but identified account can supply retained historical facts with its status visible. Check active workout/reference support independently. Read each source through owner-scoped joins, including child rows, issue subjects, and provenance hydration. Represent a canonical manual record with known owner and absent provider/account explicitly. Keep overlapping sources in separate series unless an exact canonical identity proves a shared event. Never add the generic strength report to its Hevy subset.

**Intake is an explicit exception to account selection.** Label the selected result `owner_day` and list its contributing accounts, fields and IDs. Restrict account-specific coverage labels to those accounts. Do not relabel an owner-day result as Garmin-account intake or filter out a disagreeing account. For an account-limited consumer that cannot accept owner-wide selection, return intake unavailable with reason `owner_day_scope_required`. If contributing provider days cannot be aligned, show the source facts side by side and withhold the selected calendar aggregate. An account filter for weight or activities has no effect on the owner's intake hold.

### Minimum data returned

A frozen typed `LongitudinalReport` contains the request and contract version, observations, acquisition days, daily and weekly metric rows, and exclusions. Typed rows or schema-fixed Polars frames are adequate. A weekly metric is keyed by week, metric, source scope, date basis and comparison group. Daily and weekly views reference the same facts by ID. There is no new observation table or migration.

| Result component | Required fields and meaning |
| --- | --- |
| Observation identity | Owner, provider/account or explicit manual origin, canonical entity type and ID, metric/field and parent ID. Use the stable scoped workout reference for an outing, the individual set ID for a set, and stored row IDs for recovery, intake and mass. Retain source identity or instant key when present. Child position identifies a split or step only within that activity snapshot. Imported edits can replace strength children. An existing ID can acquire a corrected value. |
| Time | Provider-local date and its meaning, nullable actual UTC instant or observation window and precision, report date and date basis. Use a workout start for session placement. Do not invent a set occurrence time, assume a midnight weigh-in or use retrieval as occurrence. |
| Provenance | Value, unit, method, canonical field, source DTO/field when known, mapper/profile version, source revision if present, and field-level retrieval time. Keep recorded availability time with its basis if stored (e.g. outcome recorded time). Use null plus a reason when first availability or commit time is unknown. A report-read time describes the read only. |
| Qualification | Acquisition category/day key, status/policy, reconciliation state, open reasons and affected subjects, execution evidence, comparison group and exclusion reasons. Examples of execution evidence are timestamp-confirmed set, Hevy-inferred set, observed outing, scoped manual actual, instruction only and inapplicable. A missing measurement can coexist with a valid outing. |
| Metric cell | Value or null, unit/method, supporting IDs, requested dates, eligible dates and count, non-null inputs / eligible inputs, exclusions by reason, and whether it is a complete source total, observed lower bound, observed sample statistic or unavailable. Carry independent acquisition and reconciliation counts. Supply backing date/ID lists once and reference them across cells. |

**Reproducibility.** Record period, IANA zone, source scope, date alignment, mapping/metric versions, Hevy inference/load profile, comparison rules and reference-window policy. Aggregate canonical units using decimal arithmetic. Sort by date basis/date, UTC instant (unknown last), account, parent/observation ID and metric. Within workouts, preserve exercise and set positions, followed by their IDs. Use canonical ID order for ties and sorted reason lists. Keep full precision through aggregation, apply documented display rounding last. Exclude run timestamps from equality checks of analytical results. Repeated reads with the same facts and policy reproduce rows and order. A later correction, deletion or new coverage legitimately changes latest-state results.

A request for an earlier calendar period reads **today's accepted version** of that period. Filtering mutable rows on retrieval time loses superseded values and can exclude a previously known value refreshed later. Historical decision replay needs values, field identities/revisions, occurrence and availability evidence, coverage, open issues, exclusions, policies and selection results frozen with the decision. If the original decision lacks those inputs, return replay unavailable. A digest verifies a retained snapshot but cannot recover it. The initial API exposes no arbitrary as-of parameter.

## Calendar, coverage and reconciliation

Use half-open local dates `[start, stop)`. A week runs from Monday 00:00 through the following Monday 00:00 exclusive in the declared calendar. Iterate calendar dates across daylight-saving transitions. Edge rows carry the intersection with the request and its day count. Only seven requested, closed dates make a full week eligible for a full-week comparison. A current, still-open source day can have verified observations and an acquisition status but cannot close the week's exposure.

Strength uses the workout start in the requested IANA zone, including all sets of a workout crossing midnight. Endurance retains both the start instant converted to that zone and the provider's activity date. Garmin coverage attaches **only** to its provider date. Sleep belongs to Garmin's assigned sleep date even if its window began the previous evening. Daily intake, expenditure, HRV and weight retain their provider calendar assignments, including weight with an actual instant. A daily aggregate without a known zone has no recoverable UTC boundary. Display the calendar/basis on each series. Align series into one local-day exposure or temporal hypothesis only with established compatible day semantics for the period. Otherwise show parallel labeled calendars, even for equal printed dates. Preserve divergent dates under travel. A re-binned activity count by instant cannot inherit complete source-day coverage without verifying all contributing source intervals.

| Acquisition evidence for one category, account and day | Interpretation in the report |
| --- | --- |
| `observed` / `empty` under the applicable policy | The requested acquisition completed with eligible results / with no eligible results for that feed. Inspect field presence, issues and retained rows separately. A successfully enumerated, closed activity day with no retained contradictory evidence supports zero observed provider sessions. An empty sleep, HRV, intake or weight response supplies no measured zero. |
| `partial` | Display independently verified active rows and known nonnegative exposure subtotals. Further sessions or measurements may exist. A date with no verified activity has unknown total. |
| `failed` / no row (`never_queried`) | Show the distinction and known retained facts. A previous success/count may survive a failed retry. The last success cannot close the current failed attempt. A legacy bounded import can supply rows without a historical coverage row. |
| No daily acquisition model | For Hevy or manual history label enumeration unknown. A set or workout can still be observed. Empty canonical weeks do not establish rest. |
| Any status plus an open issue | Display acquisition and issue separately. Withhold the affected subject/metric. A day-scoped issue holds that domain/day. Withhold the entire weight day on any open weight issue, and the owner-day intake total on selector conflict. Preserve independent, undisputed activities on the same day. An instruction issue alone does not invalidate a verified distance. |

For each scope and week count requested dates and dates in **each** acquisition state (one state per date), reconciled/held dates, dates with an eligible metric, and non-null observations. Here “reconciled” means no known open issue in scope, without asserting independent verification of every field. An eligible count can mean activity identities, instruction rows, source fields or accepted entries. Never use it as a generic session count. Partial and failed rows can retain counts from an earlier success. An empty retry never establishes deletion. For example, an active stored run followed by an empty rescan still appears as retained history with a discrepancy. Report the listing's zero separately and suppress a complete exposure total. Check retained identities, receipts where available, counts and subsequent updates against the acquisition evidence. Equal counts alone do not resolve ambiguous membership.

“Complete” applies only to the selected source, category, period and metric. Require aligned closed dates, successful enumeration throughout, eligible classifications, support for the counted population and all required field values, without unresolved discrepancies affecting the metric. A closed, fully enumerated day with zero eligible runs has zero recorded running distance and time by the empty-sum convention. If runs exist and every distance is missing, return null distance even when the count is complete. A complete activity count can accompany incomplete distance. For incomplete but unambiguous verified nonnegative contributions, publish their sum/count as a lower bound and identify missing dates/values. With no contributions and unknown coverage, publish null. With contested membership or possible duplicates, publish individually supported observations and withhold the affected aggregate until a defensible distinct subset is known. Lower bounds describe recorded exposure, never all real-world training. Selected reported intake, weight, ranges, medians and changes are sample summaries. Missing values do not turn them into lower bounds on physiology.

## Metric definitions

Group daily observations first. Build weekly totals from unique identities in the requested dates. Never sum distinct-workout counts across exercise categories. Means divide by the stated non-null sample count. For all medians below, sort eligible values and average the middle two for even samples. A zero denominator gives null. Coverage fractions always retain numerator and denominator.

### Strength

- **Frequency and consistency.** Preserve the existing count of distinct active workouts by start date, including open and empty workouts. Alongside it report distinct dates and workouts with at least one confirmed working set, plus dates and workouts with inferred working sets only. These disjoint workout counts distinguish recorded visits from evidenced work. For consistency show full weeks with any qualifying working-set day / full requested weeks, separately for confirmed work and for confirmed-or-inferred work. Label this an observed-history fraction, expose unknown acquisition weeks and omit clipped weeks. It does not measure adherence.
- **Exposure.** Count normal, drop and failure sets once per set ID. Break out warmups, unknown kinds and sets lacking completion evidence. Strict completion requires a completion timestamp. In the Hevy profile only, an untimestamped set in an ended workout with positive reps, duration or distance is inferred. Confirmed count equals eligible completed sets minus inferred sets, within each category. Only confirmed working sets enter confirmed actual exposure. For lower-body exposure use a versioned, explicit series-to-lower-body mapping reviewed for that account/equipment. Count those working sets and their distinct workouts by evidence tier. Report unmapped sets separately.
- **Task performance.** Show ordered recorded load and reps per eligible set with set kind, evidence, RPE if present, movement/variation, equipment and load convention. Use account/template or reviewed equivalent occurrences. Keep ambiguous occurrences separate. Recorded resistance can remain visible with its original convention. For comparable external-load rep sets, report known rep sum and kg·rep subtotal with `sets_with_reps` and `sets_with_load` over eligible sets. Unknown values do not contribute. A convention change breaks the series. Body mass, assistance and per-side conventions cannot supply comparable external kg by default. Report kg·reps only within the eligible series.
- **Estimated 1RM.** Reuse Epley `kg × (1 + reps/30)` for positive allowlisted external load, working kind, 1–10 reps and no positive time or distance. Apply the existing valid-RPE rule and optional inclusive RPE filter. Carry effort coverage. Select highest unrounded estimate per workout/series, ascending set ID on ties, then round half-even to 0.01 kg. Label the selected set's evidence. For a confirmed-only trend filter for confirmed execution **before** picking the best set. For comparisons select dated, same-protocol, same-evidence series. Show successive results and signed differences in recorded reps at fixed load, load at fixed reps, or eligible estimates. Compare fixed set role/ordinal where it matters. A changed protocol, unknown task equivalence or missing operand yields no difference. An estimate is modelled performance.

The existing three strength tables omit some set-level details, including ordered non-Epley sets. Factor the existing normalized observation/series preparation for reuse when adding a set-level projection. Preserve the old reader outputs and avoid reproducing Hevy metadata parsing or completion predicates in a second calculator.

### Running and other endurance activities

- **Exposure.** Count distinct active, verified running workouts and distinct running dates using canonical sport. Sum known distance in metres and report separate sums of activity seconds, moving seconds and elapsed seconds. Each sum has its own measured-session count / eligible sessions. No substitution for a missing time field. List subtype and unknown classification. Keep squash, ultimate and other sports in separate count/time/distance series where meaningful. A running-outing record establishes the outing independently of any prescribed role, interval target or slot.
- **Pace and longest run.** For each run reuse `Activity.running_pace()`, which divides 1,000 by positive reported average speed in m/s and rounds half-even to 0.001 seconds/km. Zero speed or zero distance makes pace inapplicable. Absent speed for an otherwise eligible run gives missing. Name the speed basis and keep pace at session grain. Weekly longest observed run is maximum known session distance, with duration fields on that same workout. Return the earliest UTC start then lowest workout ID on distance ties, and show measured/eligible sessions. A partial week can have a longest *observed* run while its true source-week maximum is unknown.
- **Representative weekly exposure.** Show each complete, closed seven-day week, including supported zeros, for a single source and unchanged regime. For a recent reference take the last four full calendar weeks within the request preceding the comparison week. Return the median of at least two eligible weekly totals **per metric** (e.g. running sessions/week, m/week or activity s/week). Include all eligible weeks in that window, the individual values, dates and excluded weeks. Partial weeks remain visible in daily history and weekly lower bounds. Exclude them from the representative median. The result describes the sampled source weeks. Representativeness for planning requires context about interruptions, travel and other sources. Two weeks and four weeks are reproducible reporting conventions.
- **Task performance and instructions.** List observed time, distance and pace for each outing. A signed change in elapsed time requires the same verified distance, comparable task/effort, course or protocol, timing convention and material conditions. If context is absent, retain the outings without a directional comparison. Instruction coverage has its own category and denominator, including when an activity has no instructions. Preserve aggregate split type/count and snapshot position and distinguish absent from explicitly empty collections when supported. Neither source yields chronological laps, achieved repetitions, exact intensity distribution or time in zone. Ordinary run summaries cannot establish changes in running economy, thresholds or measured VO2max.

### Recovery

Daily values are the reported metric per owner/account/provider day. Report sleep duration excluding naps in seconds, available confirmed sleep-window endpoints in UTC, and available light/deep/REM/awake seconds with their own counts. A missing endpoint leaves the corresponding timing unavailable. Avoid adding stages or awake time to total sleep. Stages are wearable classifications. Resting HR is reported bpm. Keep overnight HRV and the trailing seven-day HRV ending on that date distinct, with window, source, mapping and unit state. With `source_unit_unverified`, allow inspection of the source observation and count days present. Suppress numeric aggregation, comparisons and decision use. Overlapping trailing-seven-day observations cannot serve as independent nights. [Canonical measurement semantics](endurance-recovery.md)

For each eligible sleep metric and resting HR, report the weekly median and observed min/max over comparable observed dates with `n`, or a lone observation if `n = 1`. A **recent individual reference** for sleep duration or resting HR on date D uses the preceding 28 provider dates, excluding D and constrained to the requested period. Require at least 14 distinct eligible days spanning at least 14 calendar days from first to last, within one comparable source, metric, unit, method and measurement regime. Suppress the reference on a known regime break lacking sufficient subsequent data or if comparability cannot be established. Return median, min/max, contributing dates, omitted dates/reasons and effective n. Label these thresholds as display conventions open to review. A reference describes recorded history. It supplies no validated physiological baseline, measured restoration, combined readiness score or automatic cancellation.
